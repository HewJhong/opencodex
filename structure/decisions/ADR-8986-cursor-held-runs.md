# ADR-8986 — decision recorded under "Held Cursor runs"

- Contract owner: [providers/cursor.md](../providers/cursor.md#held-cursor-runs)

## Decision record

- 목적과 의도: Stop Grok 4.6 and 4.7 from opening most post-tool reasoning rounds with "the user wants me to continue" by keeping the Cursor stream open across a client tool call, as the Cursor Agent CLI does. Tracked in issue #8986.
- 기존 구현 및 제약 조건: The adapter cancelled the stream at the finalize grace and started a new run whose active turn was a user-shaped `Continue:` message, because Cursor rejected `resumeAction` for external models once replayed history reached a few thousand tokens (commit 4d5850e4d). Measured on a live account: 7 to 9 of about 9 reasoning rounds per run contained the phrase on an 8-file read chain; wording changes and `resumeAction` did not remove it.
- 검토한 주요 대안: Reword the Continue text for Grok (no effect); send `resumeAction` (no effect at the lengths tried); a module-level map keyed by tool call id (prototype); hold the stream for every external model; park for parallel tool calls.
- 선택한 방식: Park only a single announced bridged call on HTTP/2 for Grok 4.6 and 4.7, behind an environment variable that ships off. Key the registry by identity scope and tool call id (a client without a thread id sends a new random conversation id on every request, so it cannot be part of the key), and adopt only on a digest match of history, system text, tools, model and reasoning settings plus the call exactly as the client received it, and bind adoption to the transport policy that parked it. Charge a resume as a send. Never retry an adopted run, and raise the replay-unsafe signal once the result is written so the adapter and server do not replay it either. Allow parking after Cursor-native tools ran in the same turn, because a held stream repeats none of that work. Own a translator budget while parked. Close on any non-liveness frame.
- 다른 대안 대신 이 방식을 선택한 이유: A design audit found that matching ids does not prove the same branch and that late sibling calls arrive about 280 ms after the first, after today's 50 ms finalize grace, so a parked run could answer calls the client never saw. A single-call slice avoids that class while the parallel cut-off is handled separately. The prototype's stale abort listener closed 35 of 73 parked streams, so abort listeners are scoped to one turn.
- 장점, 단점 및 영향: Sequential tool chains no longer show the phrase and cost fewer replayed tokens. Held runs cost one socket each, bounded by 24 and a 10 minute lease; Cursor kept an idle stream for more than 14 minutes in measurement. A lost run falls back to the unchanged replay path. Parallel steps, HTTP/1, image results and non-Grok models are unchanged. Phrase removal is measured on one prompt and one model: 0 of 9 reasoning blocks in six chains and 6 of 9 in one unexplained chain, against 7 of 9 without the flag. Not verified: the checkpoint commit after several resumes, Codex CLI or App clients, long and concurrent tools.
